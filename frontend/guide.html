Guide d'utilisation

Jumeau numérique · Santé de l'équipage. L'application suit en continu les constantes des astronautes (capteurs de la combinaison) et l'environnement de la cabine, et les affiche sur un corps 3D coloré par niveau de risque. Prototype : ce n'est pas un dispositif médical.

1. Démarrer

Version Windows (exécutable)

  1. Dézippez le dossier JumeauNumerique (ne lancez pas depuis le zip).
  2. Double-cliquez JumeauNumerique.exe. Une fenêtre noire s'ouvre : c'est le serveur local, ne la fermez pas tant que vous utilisez l'application.
  3. Le navigateur s'ouvre sur l'application. Sinon, allez sur l'adresse affichée (http://localhost:8000).
  4. Au premier lancement, Windows peut demander d'autoriser le réseau : cliquez Autoriser (nécessaire pour le téléphone).
  5. Pour tester sans vrais capteurs : lancez Lancer_avec_simulateur.bat à la place.

Sur téléphone

PC et téléphone sur le même Wi-Fi : ouvrez dans le navigateur du téléphone l'adresse « Depuis un téléphone » affichée dans la fenêtre noire (ex. http://192.168.1.20:8000).

Le bouton « Changer de mode » ramène à l'écran de choix. Un badge RÉEL ou DÉMO est affiché en haut de chaque écran.

3. Créer les comptes (mode normal)

  1. Astronaute : « Créer un compte » → nom, âge (18-80), mission, rôle Astronaute, mot de passe (8 caractères min.). Un identifiant vous est donné (ex. A-01) : notez-le, il sert à se connecter.
  2. Médecin : même chose, avec la même nom de mission que ses astronautes et le code médecin. Le médecin voit tous les astronautes de sa mission (son équipage).
  3. Administration : rôle Administration + code administration. Elle voit tous les astronautes de toutes les missions et la liste des comptes.
Les codes médecin et administration sont affichés dans la fenêtre noire à chaque démarrage et enregistrés dans data\access_codes.json. Ne les donnez qu'aux personnes autorisées.

Mode démo : codes MED2026 et ADMIN2026, comptes prêts A-01, MED-01, ADM-01 (mot de passe demo), et boutons « Accès rapide ».

4. Utiliser l'application

Astronaute

Il voit son propre jumeau 3D (tournez avec le doigt ou la souris, touchez une zone pour la détailler), ses constantes (cœur, SpO₂, HRV, CO₂ de la cabine, températures…) et les mesures conseillées.

Médecin de bord

Liste de l'équipage avec une pastille par zone et un aperçu 3D. Touchez un astronaute pour ouvrir son tableau de bord complet. Chaque consultation est enregistrée dans le journal d'accès.

Administration

Onglet « Équipage » (tous les astronautes) et onglet « Base de données » (tous les comptes, sans mots de passe).

Lire les couleurs

● VertNominal
● JauneÀ surveiller
● RougeCritique : agir / prévenir le médecin

Zones : Tête (HRV, CO₂), Torse (cœur, SpO₂, température), Jambes (charge musculaire), Radiations (halo autour du corps). Chaque zone non verte affiche ses raisons et une mesure conseillée. Le message « Dernière mesure il y a … s » signifie que les capteurs n'envoient plus.

L'analyse (IA locale) compare chaque valeur aux seuils, à la normale personnelle de l'astronaute et à la tendance récente, sans connexion internet.

5. Alertes, rapport et journal d'accès

  • Alertes automatiques : dès qu'un astronaute change de niveau (nominal, à surveiller, critique), une alerte est enregistrée avec les raisons, même si personne ne regarde l'écran (mode normal). Onglet « Alertes » : l'historique, avec le nombre d'alertes critiques.
  • Bandeau rouge + son + vibration pour le médecin et l'administration quand un astronaute passe en critique. Le bouton « Son activé / Son coupé » règle le son.
  • Rapport : le bouton « Rapport » ouvre un compte rendu de l'état de l'équipage et des dernières alertes, prêt à imprimer ou à enregistrer en PDF.
  • Journal d'accès (administration) : qui a consulté les données de quel astronaute, et quand.

Installer comme une application (téléphone / PC)

Sur la version hébergée en HTTPS (GitHub Pages) : menu du navigateur → « Ajouter à l'écran d'accueil » ou « Installer l'application ». L'interface s'ouvre ensuite en plein écran et reste disponible hors ligne. Les données du mode normal viennent toujours du serveur local.

6. Brancher les vrais capteurs

Le matériel (ou une passerelle) envoie des requêtes HTTP au serveur, avec la clé capteurs affichée au démarrage (aussi dans data\ingest.key).

POST http://ADRESSE:8000/api/ingest/biometrics
X-Ingest-Key: <clé capteurs>
{"astronaut_id":"A-01","heart_rate":72,"spo2":98,"hrv":55,"body_temp":36.8,
 "skin_temp":33.2,"resp_rate":15,"bp_sys":118,"bp_dia":76,"hydration_pct":92,"muscle_load":0.5}

POST http://ADRESSE:8000/api/ingest/environment
{"mission":"Artemis III","co2_ppm":900,"cabin_temp":22,"radiation_mgy_h":0.02}

Obligatoires : astronaut_id, heart_rate, spo2, body_temp (et pour l'environnement : mission, co2_ppm, cabin_temp, radiation_mgy_h). Les autres champs sont facultatifs. Envoi conseillé : toutes les 2 à 5 secondes. Le nom de mission doit être celui du compte des astronautes.

7. Données et sécurité

  • Tout reste sur le PC dans le dossier data à côté de l'exécutable : base astro.db, mesures chiffrées AES-256-GCM, mots de passe hachés.
  • Sauvegarde : copiez tout le dossier data (en particulier aes256.key : sans elle, les mesures sont illisibles).
  • Les mesures de plus de 30 jours et les alertes de plus de 90 jours sont supprimées automatiquement ; les alertes sont chiffrées comme les mesures.
  • Pour tout effacer : fermez l'application et supprimez le dossier data.
  • Le serveur est accessible aux appareils du même réseau : utilisez un Wi-Fi de confiance.
